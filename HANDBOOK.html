OpenCode Session Tracker

An Omarchy / Quickshell plugin (bar widget + overlay panel) that turns your local OpenCode session history into a prompt workbench: browse prompts and answers, compose a payload from skills + directive + user prompt, optionally clean it up via a cheap LLM, and send it straight into a live OpenCode session — while recording every send as training data.

v0.1.0 MIT QML / Qt 6 · Quickshell Python 3 · no third-party deps io.github.aroehrscheid-lsrmnky.opencode-sessions

New user? → §3 Quick start, §4 How-to, §5 Manual. Developer / re-implementer? → §6 Architecture, §8 Panel.qml, §11 Recreate.

1 · What this is

OpenCode (the coding agent CLI) stores every session, user prompt and assistant answer in a SQLite database on your machine. That data is hard to browse, impossible to reuse, and lost between runs. This plugin makes it a UI:

  • Read — browse sessions, prompts and the LLM's answers, with search, bookmarks and keyboard navigation.
  • Compose — assemble a new prompt from a saved directive (single-select quick templates), saved library items and toggleable skills with per-skill emoji/colour.
  • Send — push the composed payload into a running or brand-new OpenCode session with one keystroke (Ctrl+Enter), optionally refined by a cheap BODI model first.
  • Learn — record every send to training.jsonl and export it as ShareGPT / Alpaca fine-tuning datasets.

It ships as a standard Omarchy plugin: a bar-widget (the little OC pill in the bar) plus a panel (a full-screen dark overlay holding a 1280×820 card). Everything runs locally on your GPU/desktop — the only network call in the whole app is the optional prompt-cleanup request to the BODI endpoint.

2 · Feature list

Session & prompt history

  • Up to 100 sessions, 50 prompts per session, exported from OpenCode's SQLite DB every 30 s by a systemd user timer.
  • Session chips with title, timestamp and a one-click ★ bookmark; a ★ Bookmarked filter narrows the chip row.
  • Session-title search in header row 2 (right-aligned), replacing the old day filters.
  • Prompt list per session with full timestamps and a per-prompt ⧉ copy button.
  • "Recent Prompts" search that matches across all sessions when you type, within the active session otherwise.
  • Collapsible Sessions group; list refreshes after every send.

Answer view (left column)

  • Click a prompt → its answer opens in the left column only, so your half-written compose draft on the right is never covered.
  • Answer n / m counter with ◀ ▶ prev/next and a List button back to the prompt list.
  • Font controls: monospace family dropdown + size slider + Refresh (re-reads the answer from cache).
  • The selected prompt stays visible above the answer, others hidden.
  • Answers render in monospace with markdown-ish text preserved (code, ASCII art, tables survive).

Compose pane (right column)

  • System Prompts — a disabled "coming soon" strip reserved for OpenCode's own standing instructions (separate feature; not yet implemented).
  • Directives — 6 seeded starter templates (Code Review, Debug Helper, Doc Writer, Refactor Guide, Test Generator, Security Audit) shown as single-select chips; the chosen directive's text appears in the editable box below. Click the active chip to deselect. The pane has its own Search directives to toggle… field between the chips and the box.
  • Directive box + User Prompt editor, with an inline Library chip that opens a saved-prompt picker in place.
  • Copy / Save to Library / Clear — right-aligned in the User Prompt header.
  • Skill chips — toggle skills on/off; each chip shows the emoji and border colour you chose in the Skills tab (22 emoji, 24 colours, custom emoji allowed). The skills pane carries its own Search skills to toggle… field in its header.
  • Skill search lives inside the Skills pane (not in the top header) — "Search skills to toggle…", and the Directives pane similarly carries "Search directives to toggle…".
  • Selected skills are injected as a Skills to use: … directive into the payload.

Send pipeline

  • Build / Plan agent segmented control (maps to opencode run --agent build|plan).
  • ✨ Clean-up — when on, the payload is first merged/self-contained-ified by BODI ornith (a small local-ish model), then sent.
  • ● Record — when on, every send appends a full JSONL record (raw + final payload, skills, agent, cwd…) to training.jsonl.
  • New Session ▶ starts a fresh OpenCode session; Send (Ctrl+Enter) continues the selected one.
  • Live vs. local. Before sending, the script probes http://127.0.0.1:4096 (/global/health + /path project check). If your TUI was started as opencode --port 4096, the send goes through that server (opencode run --attach) and the prompt appears live in the open TUI. Otherwise it falls back to a plain local opencode run, which lands in the shared SQLite store and shows up in the TUI only after you switch away and back to the session.
  • Status line reports each stage: Cleaning up prompt via BODI… → Sending… → MODE: attach …/MODE: local (…) → OK → Sent / Sent (recorded) / Send failed (exit n).
  • The exporter re-runs automatically after a send so new prompts appear immediately.

Library, Directives, Skills, Stats, Dataset tabs

  • Skills tab (Ctrl+5) — one card per skill, 2 per row: name (centred), description, 22-emoji palette, custom emoji field, 24-colour palette, reset. Persists to skill_styles.json.
  • Library tab (Ctrl+3) — saved prompts as 2-per-row editable cards: edit the text → Save (persists to prompts.json and re-derives #tags) or Revert; Delete is two-step ("Confirm?"); a bottom strip adds a new prompt via a one-line field + Add (or Enter); #tag chips filter; Export JSON / Export MD / Import (dedupes by id). Inserting a library item into the draft happens only from the Main tab's inline Library picker.
  • Directives tab (Ctrl+4) — saved standing instructions as editable cards, each with a Title, body, #tags and a single-select radio; pick one here or on the Main tab. Bottom strip adds via Title + body + Add; Export JSON / Export MD / Import (dedupes by id). Persists to directives.json.
  • Stats tab (Ctrl+6) — session count, library count, prompts in the last 30 days, active session.
  • Dataset tab (Ctrl+7) — record count, raw training.jsonl viewer, Export (ShareGPT + Alpaca).
  • Bar widget — OC pill toggles the panel, with hover feedback.

Install

cd ~/documents/opencode-session-tracker
./install.sh install      # copy plugin/ → ~/.config/omarchy/plugins/<id>/, validate, rescan
./install.sh update       # re-copy after pulling new code (never clobbers your prompts.json)

install.sh reads the plugin id straight out of plugin/manifest.json, backs up an existing prompts.json and directives.json before copying (so your prompt library and directives survive), runs omarchy plugin validate, and calls omarchy-shell shell rescanPlugins. The alternative one-liner from the Omarchy cheatsheet is omarchy plugin add <repo-url> --enable.

Start the 30-second exporter timer

systemctl --user enable --now opencode-sessions-exporter.timer
systemctl --user list-timers opencode-sessions-exporter.timer   # NEXT/LAST should tick every 30s

The unit pair lives in ~/.config/systemd/user/ and simply runs exporter.py; the panel reads the JSON it writes. Without the timer you can still refresh manually (the panel re-runs the exporter after every send).

Open the panel

  • Click the OC pill in the Omarchy bar, or
  • omarchy-shell shell summon io.github.aroehrscheid-lsrmnky.opencode-sessions '{}'
  • Closes with Esc or the bar widget only — clicking the dimmed backdrop is ignored so a stray miss-click can't dismiss the panel.

4 · Everyday how-to

  1. Pick a session. Click a chip in the Sessions row, or filter the row by title with Search session titles… (header row 2), or press ★ Bookmarked to see only starred sessions. ★ on a chip toggles its bookmark.
  2. Read the history. Type in Search all sessions… to search every prompt at once (clear it to return to the active session's list). Each row shows the full timestamp; ⧉ copies just the prompt.
  3. Open an answer. Click a prompt that has one → the Answer pane replaces the list in the left column. Step through with Ctrl+Shift+←/→, adjust font/size, hit Refresh if the answer came in late, and List to go back.
  4. Compose on the right. Pick a Directive chip for a standing instruction (its text fills the box below), then type (or load from the Library chip) your user prompt. Copy puts directive+user on the clipboard, Save to Library stores it (extracting #tags), Clear empties the draft.
  5. Toggle skills. Click chips to turn them on — they contribute a Skills to use: … line. Use the search box inside the Skills pane to find one quickly, and the Skills tab (Ctrl+5) to recolour/re-emoji them.
  6. Choose the run options. Build or Plan agent; ✨ Clean-up on = BODI merges everything into one self-contained instruction first; ● Record on = the send is appended to the training log.
  7. Send. Send (Ctrl+Enter) continues the selected session; New Session ▶ starts a fresh one. Watch the status line: MODE: attach http://127.0.0.1:4096 + Sent means the prompt is already visible in your open TUI (requires launching it as opencode --port 4096); MODE: local (…) means it was written to the shared store instead — switch sessions in the TUI to see it.
  8. Check the data. Open the Dataset tab to see the record count and export ShareGPT + Alpaca JSON when you want to train on it.
Tip — focus. The panel uses Wayland layer-shell keyboard focus OnDemand: it grabs keys only while it is the focused surface. If Ctrl+Enter does nothing, click inside the panel first (the OpenCode window behind it may still hold focus).

6 · Architecture

Everything is a small pipeline of single-purpose processes around one declarative QML file. The QML never touches SQLite or the network itself — it shells out and watches files.

        ▼                                                 ▼

Runtime components

exporter.pyThe only SQLite reader. Bounded queries (100 sessions × 50 prompts), pairs each user prompt with the last assistant message before the next prompt.

How the UI stays live

  • Seven FileView objects watch the JSON/JSONL stores; onFileChanged → reload() pushes fresh data into properties, and every visual is a binding on those properties.
  • Six Loaders in contentArea instantiate one Component per tab, so the inactive tabs cost nothing and the active one owns its layout.
  • All external work runs through Process objects; stdout lines become the status message and onExited flips flags (e.g. sending).

8.8 The send state machine

sendPayload(newSession)                 // Ctrl+Enter / Send / New Session ▶
  ├─ composeRaw() == ""  → status "Nothing to send"
  ├─ cleanupOn?
  │    yes → refineProc: stdin {"skills","directive","user","model":"ornith"}
  │           exit 0 & non-ERROR stdout → finishSend(out, newSession, cleaned=true)
  │           else                       → sending=false, "Clean-up failed (exit n)"
  │    no  → finishSend(raw, newSession, cleaned=false)
  └─ finishSend()
       build job JSON → sendJobView.setText(...) → sendProc:
       python3 scripts/send_prompt.py ~/.cache/opencode-sessions/send_job.json
         ├ probe http://127.0.0.1:4096 (/global/health + /path vs job.cwd)
         │   ok → print "MODE: attach <url>" ; opencode run --attach <url> --dir … [-s id] "<payload>"
         │   no → print "MODE: local (<reason>)" ; opencode run --dir … [-s id] "<payload>"   (stdin DEVNULL, ANSI stripped)
         └ stdout lines → status line; exit 0 → "OK"
       onExited: sending=false, status "Sent"/"Sent (recorded)"/"Send failed (exit n)",
                 exporterProc.running=true, trainingView.reload() if recording

11 · Recreate from scratch

A build order that reproduces this app without rediscovering the landmines. Total: one QML file, one exporter, twelve scripts, one manifest.

  1. Scaffold the plugin. mkdir -p plugin/scripts, write manifest.json (schemaVersion 1, a reverse-DNS id, kinds: ["bar-widget","panel"], entryPoints, keepLoaded: true), then omarchy plugin validate.
  2. Bar widget (22 lines). BarWidget { moduleName: … } containing a WidgetButton whose onPressed runs omarchy-shell shell toggle <id> '{}' via root.bar.run(...).
  3. Exporter + timer. Read-only SQLite queries against opencode.db with hard limits (100 sessions, 50 prompts), pair each user prompt with the assistant message that precedes the next prompt, write one JSON file. Add a systemd --user oneshot service + OnUnitActiveSec=30sec timer.
  4. Panel shell. Root Item with open/close → PanelWindow (all edges anchored, transparent) → dim backdrop MouseArea → centred 1280×820 card. Set WlrLayershell.keyboardFocus: OnDemand and namespace opencode-sessions-panel.
  5. State + stores. One property block, then one FileView per JSON file with watchChanges: true, printErrors: false, onFileChanged: reload(), and onLoaded handlers that assign properties (QML needs whole-object assignment to notify bindings).
  6. Header. Tab row (6 tabs ↔ viewMode) + a second row that spans the full width but pins its left-half search field to a leftColEdge marker so it lands exactly on the column split.
  7. contentArea + Loaders. Six Loaders, one Component per tab; shortcuts (Ctrl+1…7 etc.) as Shortcut items.
  8. Main left column. Session chips → prompt list (with per-row copy button) → answer pane that replaces the list (never overlay the compose side), with counter/nav/font controls and the selected-prompt box.
  9. Main right column. System Prompts reserved strip → Skills pane (chips) → Directives selector + editable box → user prompt header (left label/chip, right-aligned Copy/Save/Clear) → inline library picker → bottom send bar with a centred Row.
  10. Skills tab. A Flow whose children are half the available width (2 per row) with fixed 92 px height; two palette rows (22 emoji / 24 colours) plus a custom-emoji field; persist through a FileView.setText().
  11. Library / Directives / Stats / Dataset tabs. Library and Directives share the same shape (toolbar + tag chips + list of editor cards + Add composer); Directives adds a single-select radio per card; Dataset = counter + log viewer + export process.
  12. Scripts. Write the 12 small CLIs first with a testable contract (echo … | script, echo $?), because QML can only see exit codes and stdout lines.
  13. Send pipeline. Compose → optional refine process (stdin JSON / stdout text) → job file → send process → status text + auto re-export. Only then add Record → training.jsonl → dataset export.

QML gotchas that cost time here

SymptomFix
card.skillStylesView.setText is not a functionIds are not object properties — call skillStylesView.setText(...) with the bare id.
qmllint unintentional-empty-block on property var x: {}Write property var x: ({}) — the braces parse as a block otherwise.
Anchored child jumps/ignores position inside a Row/ColumnPositioners assign child geometry. Wrap the children in a plain Item and anchor inside that wrapper (this is exactly how the User Prompt header does left/right groups).
Clicking a swatch doesn't refresh the chipsMutating an object in place doesn't notify — reassign: skillStyles = newStylesObject.
Inner Flow width is 0 inside a ScrollViewUse <scrollId>.availableWidth, never parent.width.
Refs inside a Component resolve to nothingLoader components are separate scopes — qualify outer ids: card.selectedSkills.
Tab state vanishes when you switch tabsLoader destroys the item when inactive; accept the reset or keep the loader alive.
No errors but nothing visiblejournalctl --user --since '-2 min' for QML errors; check hyprctl layers | grep <namespace> that the window exists.
Keyboard shortcuts "don't work"OnDemand focus — click the panel first; wtype cannot drive it while another surface is focused.
qmllint: Could not find property "bordered"Known, harmless warning: bordered: true is passed to Qt Quick Controls' Button, which doesn't declare it. Style the buttons properly with a small custom Button component.
qs.Ui types unresolvedimport qs.Ui must come last.

Verification toolkit (no mouse automation needed)

  • View a non-default tab: temporarily sed -i 's/property int viewMode: 0/property int viewMode: 3/' the deployed copy, clear the qmlcache, restart, screenshot — then restore with cp plugin/Panel.qml <deployed>. (The runtime viewMode on a live screenshot is set by the user's own clicks, so a blue "Skills" tab in a photo is not a bug.)
  • Screenshot + OCR: grim -o eDP-1 shot.png then tesseract shot.png out tsv — column 7/8 = left/top, 12 = text.
  • Exact geometry: a 10-line Pillow script scanning for known colours (#252525 search fields, #3a6df0 active tab, #202020 panes) gives pixel-accurate edges — far more reliable than OCR for "is it aligned?" checks.
  • Inject state for a screenshot: a temporary Timer { interval: 3000; running: true; onTriggered: … } in the deployed copy can open a specific answer so the capture shows real content.
